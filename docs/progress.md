# Журнал разработки проекта

## Тема проекта
**Expense Tracker** — система учёта личных финансов, расходов, категорий трат и контроля бюджета.

---

## Лабораторная работа 1: Начальная настройка и базовый экран
### Результат работы
Подготовлена воспроизводимая основа веб-приложения на React 19 + TypeScript + Vite. Настроен начальный экран финансового трекера с семантической вёрсткой, базовыми стилями, карточками сводки бюджета и заглушкой для истории транзакций. Организован единый Git-репозиторий `course-app` со структурой для дальнейшего расширения (клиентский пакет `frontend`, будущие `backend` и `supabase`).

### Шаги проверки работы
1. **Проверка версий окружения:** Node.js `v24.21.0`, npm `11.19.0`, Git `2.54.0`.
2. **Проверка запуска dev-сервера:** `npm run dev` успешно стартует на локальном порту без ошибок.
3. **Проверка начального экрана:** отображение заголовка «Expense Tracker», карточек сводки и заглушки истории.
4. **Проверка строгой типизации TypeScript:** строгая типизация конфигурационного объекта, успешный `npm run build`.
5. **Проверка сборки и preview:** `npm run build` и `npm run preview` компилируют и отдают оптимизированный бандл.
6. **Проверка чистоты репозитория:** зависимости и сборочные директории исключены через `.gitignore`.

## Лабораторная работа 2: Страницы приложения и навигация

### Результат работы
1. Подключена клиентская маршрутизация на базе библиотеки `react-router` с декларативным API без перезагрузки страниц (SPA).
2. Спроектирована и типизирована сущность финансовой операции `Transaction` (`src/types/transaction.ts`), включающая 8 полей с объединениями строк для типов (`TransactionType`) и способов оплаты (`PaymentMethod`).
3. Создан массив демонстрационных данных из 6 разнообразных транзакций (`src/data/transactions.ts`).
4. Разработан единый макет `AppLayout` (`src/app/AppLayout.tsx`) с общим заголовком приложения, навигацией на `NavLink` (с точным совпадением `end` для активного состояния) и точкой монтирования дочерних страниц `<Outlet />`.
5. Создан повторно используемый компонент `TransactionCard` (`src/components/TransactionCard.tsx`) с типизированными props и выводом краткой информации, бейджей и суммы.
6. Реализованы все необходимые страницы:
   - `TransactionsPage` (`src/pages/TransactionsPage.tsx`) — список операций с ключами `key={transaction.id}` и обработкой пустого состояния;
   - `TransactionDetailsPage` (`src/pages/TransactionDetailsPage.tsx`) — карточка подробностей операции по параметру маршрута `useParams()`, отображающая все поля и содержащая безопасную проверку наличия записи;
   - `NewTransactionPage` (`src/pages/NewTransactionPage.tsx`) — заглушка экрана создания с описанием функционала ЛР 3;
   - `NotFoundPage` (`src/pages/NotFoundPage.tsx`) — экран ошибки для неизвестных путей (404).
7. Оформлены стили (`App.css`): двухколоночная адаптивная сетка (с перестроением в одну колонку на мобильных), стилизация активных ссылок, перенос длинных строк, фокус для клавиатурной навигации (`:focus-visible`).

### Шаги проверки работы
1. **Главная страница и редирект:**
   - При переходе на `/` срабатывает `<Navigate to="/transactions" replace />`, адрес в строке браузера меняется на `/transactions`, открывается список операций.
2. **Просмотр карточек и сравнение:**
   - Открыты две разные операции по ссылкам (например, `/transactions/tx1` и `/transactions/tx2`). Отображаются корректные детальные данные для каждой записи (суммы, категории, способы оплаты, описания).
3. **Прямое открытие по URL и перезагрузка:**
   - Адрес карточки `/transactions/tx1` открыт напрямую в новой вкладке и обновлён (F5). Данные загружаются стабильно благодаря извлечению `id` через `useParams()`.
4. **Экран создания:**
   - Переход по ссылке «Создать» открывает `/transactions/new`. Отображается общая навигация и понятная заглушка о добавлении формы в ЛР 3.
5. **Неизвестный адрес (404):**
   - Переход по случайному URL (например, `/unknown` или `/dashboard`) перехватывается маршрутом `*` и отображает `NotFoundPage` («Страница не найдена») с кнопкой возврата.
6. **Отсутствующая запись:**
   - Переход по валидному шаблону, но с несуществующим ID (`/transactions/missing` или `/transactions/tx999`), перехватывается проверкой `!transaction` в `TransactionDetailsPage` и выводит сообщение «Операция не найдена» со ссылкой на список.
7. **Пустой список:**
   - Проверено поведение компонента `TransactionsPage` при пустом массиве `transactions = []`: отображается карточка с сообщением «Операций пока нет» и предложением создать первую транзакцию.
8. **SPA-поведение, история, узкий экран и доступность:**
   - Переходы между экранами происходят мгновенно без полной перезагрузки HTML-документа (проверено во вкладке Network).
   - Кнопки браузера «Назад» и «Вперёд» корректно переключают историю переходов.
   - На узком экране (360px в DevTools) верстка не ломается, горизонтальная прокрутка отсутствует.
   - Элементы навигации и ссылки доступны для перемещения клавишей Tab и активации клавишей Enter с видимым индикатором фокуса.
9. **Сборка и линтинг:**
   - Выполнен `npm run lint` (`oxlint`) — 0 ошибок и 0 предупреждений.
   - Выполнен `npm run build` (`tsc -b && vite build`) — компиляция TypeScript и бандлинг без ошибок.
   - Выполнен `npm run preview` — production-сборка успешно запускается и функционирует.
