## Основной сценарий
Expense Tracker предназначен для ведения личной бухгалтерии и учёта повседневных трат. Пользователь может фиксировать расходы и доходы, распределять операции по категориям (продукты, жильё, транспорт, развлечения и др.), отслеживать общий баланс за текущий месяц и анализировать динамику расходов для контроля личного бюджета.

- **Среда выполнения и сборщик:** Node.js (v24.21.0), npm
- **Контроль качества кода:** Oxlint, строгая проверка типов TypeScript (`strict: true`)
- **Контроль версий:** Git, GitHub
- **Будущий стек (последующие ЛР):** Supabase (PostgreSQL, Auth), Node.js API

## Маршруты приложения (Адреса страниц)
Маршрутизация реализована на клиенте в режиме SPA с помощью `react-router`:
- `/` — автоматическое перенаправление (redirect с флагом `replace`) на основной список `/transactions`.
- `/transactions` — страница со списком всех финансовых операций (карточки с краткой информацией).
- `/transactions/:id` — страница подробного просмотра транзакции по её идентификатору (например, `/transactions/tx1`). Отображает все поля сущности.
- `/transactions/new` — отдельный экран создания новой операции с информативной заглушкой.
- `*` (любой неизвестный маршрут, например, `/unknown`) — экран ошибки 404 («Страница не найдена») с кнопкой возврата.
- `/transactions/missing` — сценарий отсутствующей записи по валидному шаблону маршрута: выводится специальное сообщение «Операция не найдена» и ссылка к списку.

> **Примечание о данных:** Записи в текущей версии приложения являются демонстрационными (mock-данные) и хранятся в типизированном массиве `frontend/src/data/transactions.ts`. Полноценное создание, редактирование и удаление записей через формы будут добавлены в ЛР 3.

## Запуск проекта

Из корня репозитория:

```bash
cd frontend
npm ci
npm run dev
```

После запуска в терминале отобразится локальный адрес сервера разработки (по умолчанию `http://localhost:5173/`).

## Проверка сборки и preview

Остановите сервер разработки сочетанием `Ctrl + C`. Затем выполните в каталоге `frontend`:

```bash
npm run build
npm run preview
```

Команда `npm run build` выполняет строгую проверку типов TypeScript (`tsc -b`) и собирает production-билд в директорию `frontend/dist`. Команда `npm run preview` запускает локальный сервер для предпросмотра собранного приложения.

## Текущее состояние приложения

### Лабораторная работа 1
- Развёрнут базовый каркас приложения на React + TypeScript с помощью сборщика Vite.
- Реализован начальный экран финансового трекера: заголовок приложения, карточки сводки бюджета и блок истории со заглушкой.
- Настроена строгая проверка типов TypeScript (`strict: true`).

### Лабораторная работа 2 (Страницы приложения и навигация)
- Подключён `react-router` в декларативном режиме (обёртка `BrowserRouter` в `main.tsx`).
- Описана модель предметной области `Transaction` в `types/transaction.ts` (содержит 8 типизированных полей, включая объединения строк для типов операций и способов оплаты).
- Подготовлен массив демонстрационных данных (6 записей различных типов) в `data/transactions.ts`.
- Реализован единый каркас интерфейса `AppLayout` с заголовком приложения, навигационной панелью (`NavLink` с индикацией активности и точным совпадением `end`) и областью дочернего контента `<Outlet />`.
- Создан переиспользуемый компонент карточки операции `TransactionCard` с типизированными props и стабильным ключом `key={transaction.id}`.
- Реализованы страницы:
  - `TransactionsPage` — список операций с переходом к деталям и обработкой пустого состояния;
  - `TransactionDetailsPage` — подробности операции с получением параметра через `useParams()` и безопасной валидацией наличия записи;
  - `NewTransactionPage` — заглушка экрана создания;
  - `NotFoundPage` — экран для неизвестных путей (404).
- Обновлены стили в `App.css`: адаптивная сетка (1 колонка на мобильных, 2 на планшетах/десктопах), цветовая дифференциация доходов и расходов, оформление навигации и сохранение доступного фокуса (`:focus-visible`).
